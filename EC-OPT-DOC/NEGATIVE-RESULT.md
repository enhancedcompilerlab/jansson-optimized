# 负结果记录：数字 / 关键字批量 run（探索未纳入）

把字符串批量 run 的同一思路推广到**数字扫描**与**关键字（true/false/null）扫描**：行为同样与基线等价（差分 0 不一致），插桩确认逐字节分派绝大部分已被批量消掉，但吞吐**几乎无提升（±1%，噪声内）**。

## 结论

数字/关键字 token **又短、又不受扫描主导**：

- 数字的耗时在 `strtoll`/`strtod` 数值转换 + `json_integer`/`json_real` 分配 + 对象构建；
- 关键字的耗时在 `strcmp` + 对象构建；
- 逐字节扫描开销占比极小，消掉它无收益。

字符串优化之所以有效（+90%），是因为字符串**又长、又是扫描主导**——这才是 jansson 真正值得优化的热路径。

## 度量依据（插桩）

| 负载 | 输入大小 | 走批量 run 的字节 | 吞吐（base→cand） |
|---|---|---|---|
| 数字密集（1.77MB） | 1.77MB | 1.29MB | ≈34.7 → ≈34.3 MB/s（~0%） |
| 关键字密集（2.13MB） | 2.13MB | 1.33MB | ≈63.9 → ≈64.9 MB/s（+~1%） |

## 为什么本仓库只保留字符串优化

行为等价但无收益的代码会徒增复杂度，故不纳入。此负结果的价值在于指明：jansson 的瓶颈在字符串扫描，不在数字/关键字的逐字节分派。
